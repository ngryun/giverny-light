      준비물

      1부에 필요한 것

      • 오래 쓸 이메일 주소 하나
      • 올릴 파일. 첫 화면이 될 파일 이름은 반드시 index.html
      • 인터넷 브라우저 (크롬, 엣지, 사파리 등)

      2부에 더 필요한 것

      • 프로그램을 설치할 수 있는 컴퓨터 (학교 PC는 관리자 권한이 필요할 수 있음)
      • AI 코딩 도구 이용권: Claude 유료 플랜(Claude Code) 또는 ChatGPT 유료 플랜(Codex)

      1부 · 처음 한 번

      웹에서 직접 올리기

      아무것도 설치하지 않고 github.com 화면에서만 진행합니다. GitHub 화면은 영어로 나오므로 눌러야 할 버튼 이름을 영어 그대로 적고, 뜻을 옆에 붙였습니다.

      1

      GitHub 계정 만들기

      1. github.com/signup에 들어가 이메일, 비밀번호, 사용자 이름(Username)을 입력합니다.
      2. 이메일로 온 인증 코드를 입력하면 가입이 끝납니다.
      3. 2단계 인증 안내가 나오면 휴대폰 인증 앱이나 패스키로 설정합니다. 이때 나오는 복구 코드는 꼭 따로 저장해 두세요.
      팁사용자 이름이 곧 웹 주소가 됩니다. 사용자 이름이 artteacher라면 주소는 artteacher.github.io/…입니다. 짧은 영어 소문자로 정하세요.
      2

      저장소 만들기

      1. 로그인한 뒤 오른쪽 위 + → New repository (새 저장소)를 누릅니다.
      2. Repository name에 저장소 이름을 씁니다. 영어 소문자와 하이픈(-)만 쓰세요. 예: giverny-light
      3. Public (공개)을 고릅니다. 무료 계정은 공개 저장소에서만 Pages를 쓸 수 있습니다.
      4. 나머지는 그대로 두고 Create repository를 누릅니다.
      3

      파일 끌어다 놓기

      1. 새 저장소 첫 화면에서 uploading an existing file 링크를 누릅니다. 저장소에 이미 파일이 있다면 Add file → Upload files입니다.
      2. 컴퓨터의 파일을 점선 상자에 끌어다 놓습니다. 그림이나 소리 파일이 든 폴더가 있으면 폴더째 끌어다 놓으세요. 폴더 구조가 그대로 올라갑니다.
      3. 아래쪽 Commit changes (변경 사항 저장)를 누릅니다.
      꼭 확인첫 화면이 될 파일 이름은 반드시 소문자 index.html이어야 합니다. 브라우저 업로드는 파일 하나당 25MB, 한 번에 100개까지 올릴 수 있습니다.
      4

      GitHub Pages 켜기

      1. 저장소 위쪽 메뉴의 Settings → 왼쪽 메뉴 Pages로 갑니다.
      2. Build and deployment의 Source를 Deploy from a branch로 둡니다.
      3. Branch를 main, 폴더를 / (root)로 고르고 Save를 누릅니다.
      4. 1~2분 뒤 새로고침하면 위쪽에 사이트 주소가 나타납니다. Visit site를 눌러 열어 보세요.
      주소 모양https://사용자이름.github.io/저장소이름/ 배포가 진행 중인지는 저장소의 Actions 탭에서 볼 수 있습니다. “pages build and deployment” 옆에 초록 체크가 뜨면 끝난 것입니다.
      5

      고치고 다시 올리기

      1. 컴퓨터에서 파일을 고친 뒤 3단계처럼 같은 이름으로 다시 업로드하고 Commit changes를 누릅니다. 같은 이름의 파일은 새 파일로 바뀝니다.
      2. 글자 몇 개만 고칠 때는 저장소에서 파일을 열고 연필 모양 Edit 버튼으로 바로 고쳐도 됩니다.
      3. 1~2분 뒤 사이트에 반영됩니다. 그대로 보이면 강력 새로고침을 하세요. Ctrl+Shift+R (Windows) 또는 Cmd+Shift+R (Mac).
      여기까지 하고 나면배포의 구조는 다 익혔습니다. 다만 고칠 때마다 업로드, 커밋, 확인을 반복해야 해서 번거롭습니다. 2부는 이 반복을 AI에게 맡기는 방법입니다.
      2부 · 그다음부터

      AI에게 배포 맡기기

      컴퓨터에 도구를 한 번 설치해 두면, 그다음부터는 AI 코딩 도구에게 “고쳤으니 배포해 줘”라고 말하는 것으로 1부의 일을 대신하게 할 수 있습니다. 명령어는 아래에서 복사해 터미널에 붙여 넣으면 됩니다.

      6

      터미널 열고 Git 설치하기

      시작 메뉴에서 터미널(또는 PowerShell)을 찾아 엽니다. 아래 명령을 붙여 넣고 Enter를 누르세요. 명령이 낯설면 git-scm.com에서 설치 파일을 받아 기본값으로 설치해도 됩니다.

      Cmd+Space로 Spotlight를 열고 터미널을 실행합니다. 아래 명령을 붙여 넣으면 Git이 들어 있는 개발자 도구 설치 창이 뜹니다. 설치를 누르세요.

      터미널 · Windows
      winget install --id Git.Git -e
      터미널 · Mac
      xcode-select --install

      설치가 끝나면 터미널을 닫았다가 다시 열고, 설치됐는지 확인한 뒤 이름과 이메일을 한 번 등록합니다.

      터미널 · 공통
      git --version
git config --global user.name "홍길동"
git config --global user.email "GitHub에 가입한 이메일"
      팁개인 이메일이 기록에 남는 게 싫다면 GitHub의 Settings → Emails에 있는 …@users.noreply.github.com 주소를 대신 쓰세요.
      7

      GitHub CLI 설치하고 로그인하기

      GitHub CLI(gh)는 터미널에서 GitHub를 다루는 공식 도구입니다. 여기서 한 번 로그인해 두면, AI가 비밀번호 없이 저장소를 만들고 파일을 올릴 수 있습니다.

      터미널 · Windows
      winget install --id GitHub.cli -e
      터미널 · Mac (Homebrew가 있을 때)
      brew install gh

      Homebrew가 없다면 cli.github.com에서 Mac용 설치 파일을 받으세요.

      터미널을 다시 연 뒤 로그인합니다. 질문이 나오면 차례로 GitHub.com → HTTPS → Yes → Login with a web browser를 고르고, 화면에 나온 8자리 코드를 브라우저에 입력해 승인합니다.

      터미널 · 공통
      gh auth login
gh auth status    # “Logged in to github.com” 이 보이면 성공
      8

      AI 코딩 도구 설치하기

      둘 중 이용권이 있는 쪽 하나만 설치하면 됩니다. 처음 실행하면 브라우저가 열리고 각 서비스 계정으로 로그인합니다.

      Claude Code (Anthropic)

      • Claude 유료 플랜 계정으로 로그인
      • 실행: 터미널에서 claude
      • 터미널이 부담스러우면 Claude 데스크톱 앱에서도 쓸 수 있습니다

      Codex (OpenAI)

      • ChatGPT 유료 플랜 계정으로 로그인
      • 먼저 nodejs.org에서 Node.js LTS 설치
      • 실행: 터미널에서 codex
      Claude Code 설치 · Windows PowerShell
      irm https://claude.ai/install.ps1 | iex
      Claude Code 설치 · Mac
      curl -fsSL https://claude.ai/install.sh | bash
      Codex 설치 · 공통 (Node.js 설치 후)
      npm install -g @openai/codex
      설치 명령은 바뀔 수 있어요두 도구 모두 업데이트가 잦습니다. 명령이 안 되면 공식 안내를 확인하세요. Claude Code 문서 · Codex 안내
      9

      작업 폴더에서 AI 열기

      1. 바탕화면 같은 곳에 수업용 폴더를 만들고(예: giverny-light), 그 안에 index.html과 필요한 파일을 넣습니다.
      2. 터미널에 cd와 띄어쓰기 한 칸을 입력한 뒤, 그 폴더를 터미널 창에 끌어다 놓으면 폴더 경로가 자동으로 들어갑니다. Enter를 누르세요. Windows 11에서는 폴더 빈 곳을 오른쪽 클릭해 터미널에서 열기를 눌러도 됩니다.
      3. 그 자리에서 claude 또는 codex를 입력해 실행합니다.
      4. 처음에는 “이 폴더에 어떤 파일이 있어?”라고 물어서, AI가 맞는 폴더를 보고 있는지 확인하세요.
      터미널 · 예시
      cd 여기에_폴더를_끌어다_놓기
claude          # 또는 codex
      10

      말로 배포하기

      아래처럼 무엇을, 어디에, 끝나면 무엇을 확인할지까지 한 번에 말하면 가장 잘 됩니다.

      처음 배포할 때이 폴더에 있는 파일을 내 GitHub에 giverny-light라는 공개 저장소로 올리고 GitHub Pages로 배포해 줘. 끝나면 접속 주소를 열어서 잘 나오는지 확인하고 알려 줘.
      1. AI가 명령을 실행해도 되는지 물어보면 내용을 읽고 허락합니다. 특히 지우는 명령(rm, delete)은 한 번 더 확인하세요.
      2. 끝나면 AI가 알려 주는 주소를 열어 봅니다. 처음 배포는 1~2분 걸릴 수 있습니다.
      3. 다음부터는 파일을 고친 뒤 “고쳤어. 커밋하고 푸시해서 배포해 줘.” 한 줄이면 됩니다.

      AI가 대신 실행하는 명령

      외울 필요는 없습니다. AI가 무엇을 하는지 알아볼 수 있으면 충분합니다.

      하는 일명령뜻
      기록 시작git init이 폴더의 변경 기록을 시작
      올릴 파일 고르기git add .폴더의 모든 파일을 다음 저장에 포함
      저장하기git commit -m "첫 배포"지금 상태를 메모와 함께 저장 (1부의 Commit changes)
      저장소 만들고 올리기gh repo create giverny-light --public --source=. --push공개 저장소를 만들고 바로 업로드 (1부의 2~3단계)
      Pages 켜기gh api -X POST repos/아이디/giverny-light/pages -f "source[branch]=main" -f "source[path]=/"main 브랜치를 웹으로 공개 (1부의 4단계)
      고친 것 올리기git push새 커밋을 GitHub로 보내면 Pages가 자동으로 다시 배포
      1부에서 만든 저장소가 있다면“내 GitHub 저장소 아이디/giverny-light를 이 폴더로 받아 와서, 앞으로 여기서 고치고 배포할 수 있게 해 줘.”라고 말하면 됩니다.

      AI에게 하는 말 모음

      복사해서 쓰고, 저장소 이름이나 아이디만 바꾸세요.

      고친 뒤 다시 배포index.html을 고쳤어. 바뀐 내용을 커밋하고 푸시해서 사이트를 업데이트해 줘. 몇 분 뒤 실제 주소에서 바뀌었는지도 확인해 줘.
      고치기와 배포를 한 번에물의 정원 힌트 문구를 고등학생이 이해하기 쉽게 바꿔 줘. 바꾼 부분을 보여 주고, 내가 괜찮다고 하면 배포까지 해 줘.
      웹에서 만든 저장소 이어 쓰기내 GitHub 저장소 아이디/giverny-light를 이 폴더로 받아 와 줘. 앞으로 여기서 고치고 배포할 거야.
      주소가 안 열릴 때GitHub Pages 주소에 들어가면 404가 나와. 저장소와 Pages 설정을 확인해서 원인을 찾고 고쳐 줘.
      이전 버전으로 되돌리기어제 올린 버전으로 되돌려서 다시 배포해 줘. 무엇을 되돌렸는지 먼저 알려 줘.
      설명 문서 만들기이 게임을 다른 선생님이 쓸 수 있게 README.md에 수업 방법과 그림 출처를 정리해서 함께 올려 줘.
      도움말

      자주 막히는 곳

      주소에 들어가면 404 페이지가 나와요
      • 처음 배포는 1~2분 걸립니다. 잠시 기다렸다가 새로고침하세요.
      • 첫 화면 파일 이름이 정확히 소문자 index.html인지 확인하세요. Index.html이나 index.htm은 안 됩니다.
      • Settings → Pages에서 Branch가 main, 폴더가 / (root)인지 확인하세요.
      • 주소 끝에 저장소 이름까지 들어갔는지 확인하세요. 아이디.github.io/저장소이름/
      고쳤는데 사이트가 그대로예요
      • 강력 새로고침(Ctrl+Shift+R, Mac은 Cmd+Shift+R)을 해 보세요.
      • 저장소의 Actions 탭에서 배포가 끝났는지(초록 체크) 확인하세요.
      • 고친 파일이 정말 커밋됐는지, 저장소 화면에서 파일을 열어 확인하세요.
      Pages 메뉴에 업그레이드 안내만 나와요

      저장소가 비공개(Private)여서 그렇습니다. Settings 맨 아래 Danger Zone → Change visibility에서 Public으로 바꾸세요. 공개해도 되는 파일만 들어 있는지 먼저 확인하세요.

      터미널에서 git이나 gh를 찾을 수 없다고 나와요

      설치 직후에는 터미널이 새 프로그램을 아직 모릅니다. 터미널을 완전히 닫았다가 다시 여세요. 그래도 안 되면 6~7단계 설치를 다시 확인하세요.

      푸시가 거절됐다(rejected)고 나와요

      웹 화면에서 파일을 직접 고친 뒤, 내 컴퓨터에서도 고쳐서 올리려 할 때 자주 생깁니다. AI에게 “GitHub에 있는 변경 사항을 먼저 받아서 합친 다음 다시 올려 줘.”라고 말하세요.

      파일이 너무 크다고 나와요

      브라우저 업로드는 파일 하나당 25MB, Git으로 올릴 때는 100MB가 한도입니다. 영상은 압축하거나 동영상 사이트에 올리고 링크로 넣으세요. 이미지는 가로 1000~1500px 정도로 줄이면 충분합니다.

      학교 컴퓨터에 설치가 안 돼요

      프로그램 설치에는 관리자 권한이 필요할 때가 많습니다. 학교 정보 담당 선생님과 상의하거나, 설치가 필요 없는 1부 방식으로 진행하세요.

      안전하게 쓰기

      공개 저장소는 누구나 봅니다학생 이름, 얼굴 사진, 성적, 연락처 같은 개인정보는 넣지 마세요. 저장소의 수정 기록에도 남습니다.
      그림과 음악의 저작권퍼블릭 도메인(위키미디어 공용의 옛 명화 등)이나 직접 만든 자료를 쓰고, 출처를 README에 적어 두세요.
      비밀번호와 토큰은 어디에도 붙여 넣지 않기로그인은 gh auth login으로 끝냅니다. AI 채팅창이나 파일에 비밀번호, 토큰, API 키를 적지 마세요.
      AI가 실행하려는 명령 읽기허락하기 전에 무엇을 하려는지 확인하세요. 모르겠으면 “이 명령이 무슨 일을 하는지 먼저 설명해 줘.”라고 물어보면 됩니다.
